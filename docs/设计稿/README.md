## 三条硬规矩

1. **先做版式,再做内容。** 第一轮只对:导航在哪、几栏、标题什么样、插画什么风格。
   版式没确认之前不要开始填块。
2. **说「按设计稿做完了」之前,先出一张并排对比图**(稿子 | 截图,拼在一起)。
   所有自检如果都是拿页面和它自己比(溢出、点击目标、死按钮),那是永远发现不了
   版式错的——那些检查全过,页面照样和稿子毫无相似之处。
3. **32 张图就打开 32 张。** 这次从会话记录里恢复了 32 张用户发的图,只打开 3 张
   就宣布「逐块核完了」,于是漏掉了真正的主办方控制台稿。

## 做法和稿子不同、但是有理由的

- **主办方看板**:稿子③是表格,实际做成了卡片。表格塞不下「报名/确认」的填充条,
  而一个人同时办四场活动时,扫的就是那根条
- **活动发现的分类胶囊**:稿子是固定七类(线下/线上/Monad/AI/开发者/社区)。
  合约里没有分类这个概念,tags 是自由文本,所以胶囊改成「这条链上真实出现过的
  标签」。链上没活动就不出现这一排
