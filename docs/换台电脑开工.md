# 换一台电脑改这个网站

结论:**可以,克隆 GitHub 就够了。** 没有任何东西只存在这台机器上。

> 这份只讲**环境怎么搭、怎么上线**。如果是让 AI agent 接手,还要让它读仓库根目录的
> `CLAUDE.md` —— 那份讲的是**怎么改才算改对**(红线、设计稿规矩、验证方法)。
> Claude Code 会自动读根目录的 `CLAUDE.md`,不用手动喂。

线上站 <https://zhxinyue29.github.io/peerproof/> 是 GitHub Actions 自动构建的 ——
**推到 `main` 就上线**,不需要在本地打包、不需要上传文件、不需要任何密钥。
正式环境用的那几个值(合约地址、RPC、Privy App ID、起始区块)全部写死在
`.github/workflows/pages.yml` 里,在仓库里、在历史里,谁 clone 都一样。

---

## 一、那台电脑要装什么

| | 用来干嘛 | 不装会怎样 |
|---|---|---|
| **Git** | 拉代码、推代码 | 干不了活 |
| **Node 22** | 跑本地预览 | 只能盲改,推上去才知道对不对 |
| GitHub 的登录凭据 | 推代码 | 能看能改,**推不上去** |

**不需要装** Foundry / anvil —— 合约已经部署好并且锁死了,改网页碰不到它。

GitHub 凭据用 SSH key 或者 HTTPS 的 personal access token 都行,在那台电脑上自己配
(这一步只能您自己做,密钥不该经第三方的手)。仓库是 `zhxinyue29/peerproof`,
要有写权限。

---

## 二、开工四步

```bash
git clone https://github.com/zhxinyue29/peerproof.git
cd peerproof/web
npm ci
```

> **在台式机(这台 Linux)上要加代理。** 这台机器连不上 GitHub 的 22 端口,
> 官方的 443 回退口(`ssh.github.com:443`)直连也不通,只有走本地代理才行:
>
> ```bash
> git -c http.proxy=http://127.0.0.1:7897 clone https://github.com/zhxinyue29/peerproof.git
> ```
>
> 别的电脑不用加。另外这台机器上**本来就有一份完整仓库**在 `~/文档/Monad_Circle`,
> 继续改用那个就行,不用重新克隆。

然后新建 `web/.env.local`,**原样贴下面这段**(全是公开值,没有一个是密钥):

```
NEXT_PUBLIC_CHAIN=testnet
NEXT_PUBLIC_RPC_URL=https://testnet-rpc.monad.xyz
NEXT_PUBLIC_ESCROW_ADDRESS=0xEa057c5a6F431eFF29F573E4db4bc49cD52Ee679
NEXT_PUBLIC_EVENT_ID=latest
NEXT_PUBLIC_DEPLOY_BLOCK=63497445
NEXT_PUBLIC_PRIVY_APP_ID=cmtxucm3301vy0dl7brfcv0ev
```

这个文件**不会进仓库**(`.gitignore` 里),它只管本地预览,连的是和线上同一条测试网、
同一个合约 —— 所以本地看到的活动就是线上的活动。

```bash
npm run dev        # 打开 http://localhost:3000
```

改完推上去:

```bash
git add -A && git commit -m "改了什么" && git push origin main
```

推完 **2–3 分钟**线上就变了。构建进度在仓库的 Actions 页看。

## 三、推完必须去线上看一眼

Actions 打绿勾 **不等于** 页面是对的 —— 这个项目已经被骗过一次:
workflow 全绿、站点正常打开,展示的却是一场早就结束的活动,因为有人在 GitHub 后台
设了一个变量把它钉死了,而那个变量在代码里、在构建日志里、在页面上都看不见。

所以推完以后:**真的去 <https://zhxinyue29.github.io/peerproof/> 刷一下,看改的地方变了没有。**
浏览器可能有缓存,强刷(Ctrl+Shift+R)。

---

## 四、四条别碰的线

1. **`contracts/src/EventDirectory.sol` 锁死了,一个字符都别改**(连注释都不行)。
   它的地址是从字节码算出来的,字节码里含源码的哈希 —— 改一个注释,地址就变,
   已经写在链上的所有活动标题、简介、标签**全部变成读不到**。
   旁边的 `EventDirectory.sol.LOCKED` 写了完整原因。

2. **`web/lib/wallet.ts` 里那几句英文别翻译成中文。** 那段文字是用来签名的,
   签名的结果派生出用户的密钥。字改了,派生出来的就是**另一个账号**,
   老用户的身份直接找不回来。

3. **Privy 的 App Secret 永远不要放进仓库,也不要发给任何人。**
   `.env.local` 和 `pages.yml` 里那个 `cmtxucm...` 是 **App ID**,是公开的,
   本来就要打进前端包里 —— 真正拦截滥用的是 Privy 后台的域名白名单。
   App Secret 是另一个值,这个项目**根本不用它**。

4. **别在 GitHub 后台设仓库变量**(Settings → Secrets and variables → Actions)。
   要改构建用哪个合约、哪场活动,**直接改 `pages.yml` 那一行** ——
   这样原因留在 diff 里看得见。后台变量看不见,坑过一次(见上面第三节)。

## 五、两台电脑来回换的时候

开工前先 `git pull`。两边同时改同一个文件会冲突,冲突本身好解,
麻烦的是没 pull 就改、改完发现推不上去。

本机(这台)另外还有一套 anvil 本地链的工具(`scripts/dev-chain.sh`、
`?dev=1` 一次性密钥、`scripts/demo/seed-event.mjs` 一键建填满内容的活动),
那些是**自动化测试**用的,改网页不需要。要用的话看 `docs/待办.md` 最后一节。
