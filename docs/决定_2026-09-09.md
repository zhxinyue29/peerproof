## 为什么这么定

### 名字：PeerProof

原名两个问题：**「Circle」和 USDC 发行方 Circle 撞名**（V1 文档里还有「Circle Pay」，Circle 自己就做支付，在支付赛道上是真风险）；产品已收缩成出席结算，"Circle" 不再描述它。

PeerProof 把机制写进名字。Pitch：*"Proof by peers, at conversation speed."*

**rpId 必须设在顶级域 `peerproof.io`**。WebAuthn 凭证 scoped 到顶级域时对所有子域有效；设在 `app.peerproof.io` 就锁死了，以后换子域会废掉所有 passkey。

**铁律：只在正式域名创建 passkey，永远不在 Vercel preview URL 上碰 passkey。**

### 押金：30 MON

之前定 0.05 MON 时，150 笔见证的 gas（2.34 MON）≈ 整个押金池（2.5 MON），经济上崩。

改 30 MON 后：人均 gas 0.047 MON = 押金的 **0.16%**；满场池 1500 MON ≈ $39；全场 gas $0.06；demo 三个账户共 90 MON ≈ **$2.34**。

附带效果：10 MON 储备金问题从「机制不可行」降级为「33% 开销」，不再是阻塞项。

### 账户层：Mera，不上 4337

Mera 产出的是**普通 secp256k1 EOA**，于是 **bundler / EntryPoint / paymaster / gas 池全部不需要**。

能这么砍的前提是目标用户自持 MON（定位已收窄），因此不需要赞助；而「用户看不到 gas」这个体验目标靠**本地签名不弹窗**达成，不靠代付。主网 paymaster 全部要付费订阅，砍掉它同时省钱省依赖。

合约侧零改动——`attestKey` 的形态和 Mera 输出天然一致。

**放弃 Coinbase Smart Wallet / 链上 P256 路线**：它要 4337 → bundler → 主网付费，且只支持 EntryPoint v0.6。它解决的 PRF 覆盖率风险，用一个降级按钮更便宜。

### 赛道：Consumer & Payments

Track 4 官方示例写的是 "Passkey-native accounts using **P256 and WebAuthn**"，而我们用 Mera（PRF→secp256k1，**不碰 P256 预编译**），本来就不匹配那句。

更重要：核心创新是**同伴见证机制**，不是 passkey 账户。打 Track 4 会被拿去和纯身份基础设施比。

## 已完成（本轮）

**域名不用买了。** rpId 只在创建第一个 passkey 时生效，那是前端阶段的事，现在不阻塞。用 Vercel 免费生产 URL `peerproof.vercel.app` 即可——真正的要求只是「10 月 13 日之前不改」，不是「永久不变」。`vercel.app` 在 Public Suffix List 里，所以 rpId 只能设完整主机名，作用域天然隔离。**铁律不变：per-deployment 的临时 URL 上绝不碰 passkey。**

### ✅ 场地信标已实现

`createEvent` 增加 `beaconKey` 参数（场地屏幕持有的临时密钥）；`attest` 现在要验两个签名：

1. 被见证者的滚动码（15 秒周期）
2. **场地信标签名**（`BEACON_EPOCH` = 120 秒，慢一档，免得每 15 秒重扫场地屏幕）

外加一条几乎免费的加固：**`_maybeConfirm` 要求 `gaveCount >= 1`**——你必须自己至少见证过别人一次才算到场。因为提交见证必须持有新鲜的场地信标，所以**所有被确认到场的人都必然真的在现场过，无法被朋友"代签进来"**。没有这条，三个现场同伙就能刷无限个远程账户。

还加了 `setBeaconKey`（主办方在窗口开启前可换，之后锁死，防止用它作废已提交的见证）。

**测试从 26 项增至 34 项，全绿。** 新增覆盖：伪造信标、过期信标、上一个信标周期仍有效、信标密钥换发、窗口开启后锁定、以及核心那条「收到 K 个见证但没见证过别人 ≠ 到场」。

写测试时发现一个**产品要求**：原来的 `_mutualAttest` 辅助函数里最后一个人永远只是被扫方，按新规则不算到场。**App 必须主动催用户「去扫至少一个人」，不能只显示自己的码。**

### ✅ 押金改 30 MON，gas 不再是问题

`attest` 因为多了一次 ecrecover 涨到 **199,532 gas**（+31%），但按 30 MON 押金算：

| | |
|---|---|
| 单笔见证 | 0.020 MON ≈ $0.00053 |
| 人均（3 笔） | 0.061 MON = **押金的 0.2%** |
| 满场（150 笔） | 3.05 MON ≈ $0.08 |

之前 0.05 MON 时 gas 占押金池 94%，现在 0.2%。

**因此 storage 打包优化降级为「锦上添花」**——它本来是为了救经济模型，而经济模型已经靠提高押金救了。留作 V2（顺带能当"为 Monad 存储模型专门设计"的叙事素材）。

## 仍然待验证 / 已知风险

- **物理在场无法链上证明**。场地信标把远程串通成本从「零」提到「至少一个同伙必须真的到场并转发信标」，**没有消除**。已写入 README 的 Limitations。
- **PRF 在桌面 Chrome 本地 passkey 上不可用**（实测报 `PRF_UNAVAILABLE`）→ 必须有降级按钮，**demo 用 iPhone 录**
- **10 MON 储备金对普通 EOA 的确切行为**未验（部署时顺手验）
- **Mera v0.2.0 是 preview 软件**，v1.0 前 API 可能变
- **passkey 丢失 = 资金丢失**，Mera 不提供恢复机制 → demo 账户别放多余的钱
- 判定用朴素阈值而非 K-core，会把「来自未到场者的见证」计入（V2 优化，README 已说明理由）
- 整数除法尾款留在合约里（可忽略量级，但**绝不能像 Kickback 那样给主办方**）
