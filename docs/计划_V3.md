## 三、产品最终形态

### 一句话

> 线下活动押金平台。押金由合约托管，到场者互相扫码见证出席，见证够数自动分钱——主办方没有放款按钮，结算不需要任何人动手。

### 六个屏幕

**1. 活动落地页** `/e/[id]`
活动名、时间、地点、押金金额（**显示法币等值，不显示 MON**）、已报名人数、见证阈值。核心是一个收益预估：

```
押金            ¥5.60
若你到场         取回 ¥5.60 + 按当前报名数预估分得 ¥12.40
若你缺席         押金被到场者瓜分
```

**2. 报名** —— 刷脸建 passkey → 质押押金。全程无助记词、无插件、看不到 gas。

**3. ★ 见证现场** `/floor` —— **产品的心脏，也是 demo 的核心镜头**

```
┌─────────────────────────────┐
│  见证窗口剩余  08:42        │
├─────────────────────────────┤
│      ███ 我的码 ███         │  ← 大二维码
│      ◔ 11s 后刷新           │  ← 倒计时环在缩
├─────────────────────────────┤
│  [ 扫码见证他人 ]  [场地 ✓] │
├─────────────────────────────┤
│  被见证   ●●○   2/3         │  ← 格子逐个亮
│  ✓ 0x3C44…93BC  已上链 0.31s│  ← 每行带真实上链耗时
├─────────────────────────────┤
│  全场确认到场  ████░░  12/47│
└─────────────────────────────┘
```

那些 `0.31s` 是**整个 pitch 的物证**：不是「Monad 很快」这句话，是一行行真实上链耗时。

**4. 场地信标屏** `/venue` —— 门口一台笔记本或备用手机，显示 30 秒滚动的信标码。**这块屏幕是「在场」的物理锚点**，但每人整晚只扫它一次：进门时签到（一笔独立上链交易），之后作证不再需要它。

**5. 结算与领取** —— 窗口关闭 → 自动结算 → 「取回 ¥5.60 + 分得 ¥12.40 = **¥18.00**」+ 交易 hash 链接。

**6. 主办方后台** —— 建活动、看报名、开关窗口。**放款按钮的位置故意留空，写一行灰字：**

> `Settlement is automatic. You cannot release or withhold funds.`

**把「主办方无权」做成看得见的 UI 事实，而不是文档里的一句话。** 评委会专门去找那个按钮，找不到，那一刻差异化就成立了。

## 四、Demo 视频脚本（2:30）

三台手机并排放桌上，一次录完。**用 iPhone 录**（PRF 支持最稳）。

| 时间 | 画面 | 讲什么 |
|---|---|---|
| 0:00–0:20 | 一张免费报名页 / 空荡的会场 | 免费报名零成本弃约，主办方按报名数订了场地餐饮 |
| 0:20–0:40 | 主办方后台建活动 → **镜头停在没有放款按钮那行灰字上** | 主办方从这一刻起就碰不到这笔钱 |
| 0:40–1:00 | 三台手机分别刷脸报名，真实交易 | 无助记词、无插件、看不到 gas |
| **1:00–1:50** | **核心镜头**：扫场地屏 → 互相扫码 → 格子逐个亮 → `0.31s` `0.28s` 一行行滚出 → 全场进度跳动 | 房间在给自己作证；这个速度是机制成立的前提 |
| 1:50–2:10 | 第三台手机故意不参与；窗口关闭；自动结算；两人收钱，第三人押金被瓜分 | 机制真的在判定，不是摆设 |
| 2:10–2:30 | prior art 对照 + Roadmap 架构图 | Kickback / Unlock 都是主办方说了算；我们不需要 |

### 三个必须拍到的镜头

1. **三机同屏的真实同时性** —— 一台点确认，另两台一秒内跳出成员数 +1
2. **屏幕上的真实上链耗时** —— 这是「为什么是 Monad」的唯一硬证据
3. **后台缺失的放款按钮** —— 这是「为什么不同」的唯一硬证据

### 第三台手机故意不参与

**这个反面案例比三台全成功更有说服力。** 它证明机制在判定，而不是在演。

### 铁律

**画面里出现的每个功能必须真的能跑。** 可以用 AI 配音、字幕、镜头缩放，但**不能生成假的交易成功画面**。Roadmap 只用架构图讲，不放假界面。

## 五、提交材料清单

| 字段 | 内容 |
|---|---|
| Problem | 免费报名零成本弃约；主办方已按报名数付了场地餐饮 |
| Solution | 出席由到场者互相见证产生，合约按见证图谱自动结算，主办方无放款权 |
| Why Monad | 两分钟内 150–250 笔并发见证（各写独立存储）+ 0.3 秒确认；码 15 秒过期要求确认快于过期，签到更是要求交易在 30 秒信标周期内落块。串行链只能退化成链下批量提交，那就重新引入了要信任的服务器，机制不成立 |
| What's onchain | 押金、见证、出席判定、结算、防重复领取。聊天/展示数据链下 |
| Prior art & delta | Kickback（2018，已死）/ Unlock「I'm Going」（2024，beta）= 主办方签到；本项目 = 去掉这个信任点。Unlock 官方说缺席者的钱「未来甚至可以分给到场者」——**that is the part nobody built** |
| Limitations | 物理在场无法链上证明；押金必须是用户自己的 MON；PRF 覆盖率；passkey 丢失=资金丢失 |
| Revenue | 只从缺席者被没收的部分抽成，永不碰到场者本金。**V1 故意不实现**——收款地址是特权地址，而「零特权方」是唯一的差异点 |

**要交的东西**：GitHub 仓库、公网 demo URL、主网合约地址、关键交易 hash（建活动/报名/见证/结算各一笔）、架构图、2:30 视频、bounty 申报（Mera×2、Envio、CRE）。
